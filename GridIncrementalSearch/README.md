# Blazor Grid - Incremental Search

## Overview

This sample demonstrates incremental keyboard search in a .NET 8 Blazor WebAssembly application using the Syncfusion Blazor Data Grid. The grid is bound to a locally generated collection of strongly typed category records. It supports Excel-style filtering, single-row selection, virtualization, and a custom category column template. When the grid is focused, typing searches for categories that begin with the entered text and selects and scrolls to the next match.

## Key Features

- Uses the Syncfusion Blazor Data Grid as the primary data presentation component.
- Binds the grid to a local `List<ColumnPickerItem>` generated by the home page.
- Generates up to 500 sample category records across financial, operational, administrative, system, and other categories.
- Supports case-insensitive incremental search, including multi-character input with a 500 ms typing buffer.
- Selects and scrolls to the next matching row; search continues from the selected row and wraps through the data.
- Searches the currently filtered records when grid filtering is active.
- Enables Excel-style filtering, single-row selection, and grid virtualization.
- Uses a custom template to display category names in the grid.
- Uses the Syncfusion Blazor Grid and Themes NuGet packages with the Fluent 2 theme.
- Provides a responsive page layout with a centered heading and no left-side navigation.

## Prerequisites

- .NET 8 SDK
- Visual Studio, Visual Studio Code, or another .NET-compatible IDE

## How to Run the Project

### Visual Studio

1. Open `GridIncrementalSearch.slnx`.
2. Restore the NuGet packages.
3. Build the solution.
4. Run the application and open the home page.
5. Focus a row in the grid and type to search for a category.
6. Use the column filter menu to filter the sample data and search within the filtered results.

### Visual Studio Code

1. Open the repository folder in Visual Studio Code.
2. Open the integrated terminal and navigate to the project directory.
3. Restore the NuGet packages and start the application:

```sh
dotnet restore
dotnet run
```

Open the local URL printed by `dotnet run`. The configured HTTP launch profile uses `http://localhost:5178`.
